# kuration

A semantic bookmark API. Every bookmark is embedded at save time, so a link can be
retrieved by what it is about rather than by the words in its title. Search "how does
React schedule rendering" and get back the bookmark you filed as "interesting read".

This repository contains the backend only: Next.js App Router route handlers, the Prisma
schema, and the embedding and validation helpers. There are no UI pages.

## Features

- Semantic search over a user's own bookmarks, ranked by cosine similarity.
- Embeddings generated by Voyage AI (`voyage-2`) from the bookmark's title, description
  and tags combined.
- Search filters: required-tag intersection, similarity threshold, limit and offset
  pagination. Every response reports `total` so clients can page correctly.
- Full CRUD on bookmarks. An update re-embeds the record so search stays consistent with
  the edited text.
- GitHub OAuth via NextAuth with a Prisma adapter and JWT sessions.
- Ownership checks on every per-record route: a bookmark belonging to another user
  returns 403, not 404-by-accident.
- Field validation shared between create and update paths (URL parsing, 20-tag cap,
  50-character tags, 200-character titles, 2000-character descriptions).
- In-memory sliding-window rate limit of 60 requests per minute per user, returning 429
  with a `Retry-After` header.
- Required environment variables are checked at import time, so a misconfigured deploy
  fails at boot rather than on the first request.

## Architecture

```
POST /api/bookmarks
   title + description + tags  ──►  lib/embeddings.embed()  ──►  Voyage AI
                                                                    │
                                            JSON.stringify(vector)  ▼
                                    Prisma ──► SQLite  Bookmark.embedding (TEXT)

GET /api/search?q=...
   q ──► embed() ──► queryVec
                        │
   Bookmark.findMany({ userId, embedding != null })
                        │
                        ▼
   cosineSimilarity(queryVec, JSON.parse(row.embedding))
                        │
        filter(score > threshold) ─► filter(all required tags)
                        │
                  sort desc ─► slice(offset, offset + limit)
```

SQLite has no vector type and no ANN index, so embeddings are stored as
JSON-stringified float arrays and scored in process. That is a deliberate trade: it keeps
the whole thing a single file with no extra services, at the cost of a linear scan per
query. Rows whose embedding fails to parse are skipped rather than aborting the search.

| Path | Role |
|---|---|
| `app/api/bookmarks/route.ts` | List and create bookmarks |
| `app/api/bookmarks/[id]/route.ts` | Update and delete, with ownership checks |
| `app/api/search/route.ts` | Embed the query, score, filter, paginate |
| `app/api/auth/[...nextauth]/route.ts` | GitHub provider, Prisma adapter, JWT sessions |
| `lib/embeddings.ts` | Voyage API call and cosine similarity |
| `lib/validation.ts` | Field validators shared by create and update |
| `lib/rateLimit.ts` | Per-user sliding window counter |
| `lib/env.ts` | Startup check for required environment variables |
| `prisma/schema.prisma` | User, Account, Session, Bookmark |

## Quickstart

```bash
git clone https://github.com/peteroyce/kuration
cd kuration
cp .env.example .env.local
npm install
npm run db:push
npm run dev
```

Environment variables (from `.env.example`):

| Variable | Required | Notes |
|---|---|---|
| `DATABASE_URL` | yes | e.g. `file:./dev.db` |
| `NEXTAUTH_SECRET` | yes | at least 32 characters |
| `NEXTAUTH_URL` | yes | e.g. `http://localhost:3000` |
| `VOYAGE_API_KEY` | yes | Voyage AI embeddings key |
| `GITHUB_ID` | for sign-in | GitHub OAuth app ID |
| `GITHUB_SECRET` | for sign-in | GitHub OAuth app secret |

`NEXTAUTH_SECRET`, `NEXTAUTH_URL` and `VOYAGE_API_KEY` are enforced by `lib/env.ts`.
`npm run db:studio` opens Prisma Studio against the same database.

## API

All routes require an authenticated NextAuth session.

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/bookmarks?tag=` | List own bookmarks, newest first; optional single-tag substring filter |
| `POST` | `/api/bookmarks` | Create a bookmark and embed it |
| `PATCH` | `/api/bookmarks/:id` | Partial update; re-embeds from the merged fields |
| `DELETE` | `/api/bookmarks/:id` | Delete a bookmark |
| `GET` | `/api/search` | Semantic search |

Search parameters: `q` (required, max 500 chars), `tags` (comma-separated, results must
carry all of them), `threshold` (0–1, default 0.3), `limit` (default 20, max 100),
`offset` (default 0).

```bash
curl -X POST http://localhost:3000/api/bookmarks \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com/fiber","title":"React Fiber architecture deep-dive","tags":["react","perf"]}'

curl 'http://localhost:3000/api/search?q=how%20does%20React%20schedule%20rendering&tags=react&limit=10'
```

Search responds with `{ results, query, total, limit, offset }`, each result carrying its
`score`.

Creating a bookmark fails with 503 if the embedding call fails — an unsearchable bookmark
is worse than none. Updating is more forgiving: if re-embedding fails, the previous vector
is kept and the edit still lands.

## Testing

```bash
npm test
```

Jest with `ts-jest`. Prisma, NextAuth and the embedding client are mocked, so the suite
needs no database, no OAuth app and no network. Coverage is on the route handlers:
auth rejection, validation limits, cross-user 403s, similarity ordering and tag
intersection. GitHub Actions runs the same command on push and pull request
(`.github/workflows/ci.yml`).

## Known limitations

- The rate limiter is per-process and in memory. On a serverless host each invocation is
  isolated, so it does not enforce a global limit. A Redis-backed limiter would be needed
  for that.
- Search loads every embedded bookmark for the user on each query. Fine for thousands of
  rows, not for millions.
- `GET /api/bookmarks?tag=` matches against the raw JSON tag string, so it is a substring
  match rather than an exact tag match. The `tags` filter on `/api/search` is exact.
